Standalone testing handbook

Test JEDI one API at a time.

Open these pages directly in a browser. Each route shows what to send, what must exist first, what result to expect, and one failure worth checking. No Postman environment or documentation server is required.

Base URL: every example uses http://localhost:8000. On Vercel, replace it with https://YOUR-PROJECT.vercel.app/svc/ml.

One-time preparation

cd D:\ML\JEDI
npm run user:bootstrap
npm run dev:api

Enter a private email and a password of at least 12 characters during bootstrap. Keep the server terminal open. Visit http://localhost:8000/docs only if you want an additional live schema view.

Authentication

Send the login request first. Postman keeps the returned HTTP-only jedi_session cookie for later requests to the same host. User routes need that cookie. Worker routes instead need X-JEDI-SERVICE-TOKEN; lease operations also need X-JEDI-LEASE-TOKEN. The cron route uses its own Bearer secret.

Values you will copy

Responses provide IDs needed later. Replace the manual placeholders exactly: PASTE_PROFILE_ID_HERE, PASTE_MODEL_ID_HERE, PASTE_BATCH_ID_HERE, PASTE_JOB_ID_HERE, PASTE_RUN_ID_HERE and PASTE_LEASE_TOKEN_HERE.

GET/api/dashboard

Read today's shared jobs and ranking leaderboard with the signed-in member's private viewed/application state.

http://localhost:8000/api/dashboard?leaderboardPeriod=daily&fresh=true&notApplied=true
Periods
daily, weekly or overall.
Expect
200 with todayJobs and leaderboard. Fresh excludes only jobs viewed by this member; notApplied uses only this member's application.
Failure
Invalid period returns 422.
Current boundaries: direct embedding and scoring deliberately return 501. Real SMTP needs Gmail configuration. Ranking can be tested today through the authenticated manual rankings endpoint. Rotate the Neon password that was shared in conversation before production use.
