Email and ML boundary

Email is configuration-driven. Stored rankings survive SMTP failure. Normalization works now; embeddings and scoring intentionally do not.

Email setup: set EMAIL_ENABLED=true, Gmail SMTP user, Gmail app password, DIGEST_TO_EMAIL, EMAIL_FROM_NAME and a 32+ character CRON_SECRET in the ignored .env, then restart the API. Never paste those secrets into request bodies.

GET/api/email/settings

Inspect safe newsletter configuration and recipient capacity.

http://localhost:8000/api/email/settings
Expect
200 with enabled, senderName, sendAfterRanking, transportConfigured and activeRecipientCount. SMTP credentials are never returned.
Failure
Without a session cookie expect 401.

PATCH/api/email/settings

Update newsletter behavior without placing secrets in the database.

http://localhost:8000/api/email/settings
{ "enabled": true, "senderName": "JEDI Daily Dispatch", "sendAfterRanking": true }
Expect
200 updated settings.
Failure
Enabling without complete SMTP environment settings returns 409; empty JSON returns 422.

GET/api/email/recipients

List newsletter recipients.

http://localhost:8000/api/email/recipients?active=true&includeDeleted=false
Expect
200 array. Copy a recipient ID.
Failure
Invalid Boolean query values return 422.

POST/api/email/recipients

Add, replay or reactivate one normalized recipient.

http://localhost:8000/api/email/recipients
{ "email": "friend@example.com", "displayName": "Friend" }
Expect
201 for a new row; an identical replay is idempotent.
Failure
Invalid email returns 422; the 51st active recipient returns 409.

GET/api/email/recipients/PASTE_RECIPIENT_ID_HERE

Inspect one safe recipient record.

http://localhost:8000/api/email/recipients/PASTE_RECIPIENT_ID_HERE
Expect
200 with active/deleted timestamps.
Failure
Unknown ID returns 404.

PATCH/api/email/recipients/PASTE_RECIPIENT_ID_HERE

Edit, disable or reactivate a recipient.

http://localhost:8000/api/email/recipients/PASTE_RECIPIENT_ID_HERE
{ "displayName": "Updated Name", "active": false }
Expect
200 updated row.
Failure
Empty JSON or null active/email returns 422.

DELETE/api/email/recipients/PASTE_RECIPIENT_ID_HERE

Soft-delete a recipient from future sends while preserving delivery history.

http://localhost:8000/api/email/recipients/PASTE_RECIPIENT_ID_HERE
Expect
204 with no body.
Failure
Unknown ID returns 404.

POST/api/batches/PASTE_BATCH_ID_HERE/email-digest

Manually queue or retry the latest successful batch digest.

http://localhost:8000/api/batches/PASTE_BATCH_ID_HERE/email-digest
Auth
User cookie
Body
None
Expect
200. With email disabled, delivery is null; when enabled, inspect status and attempts.
Failure
An unranked batch returns 409. A SENT digest is not sent again.

GET/api/batches/PASTE_BATCH_ID_HERE/email-deliveries

Inspect safe delivery status without recipient or message bodies.

http://localhost:8000/api/batches/PASTE_BATCH_ID_HERE/email-deliveries
Auth
User cookie
Expect
200 history with PENDING, SENDING, SENT or FAILED status.
Check
SMTP failure must leave the batch RANKED and store a bounded safe error.
Failure
Unknown batch ID returns 404.

GET/internal/email-deliveries/run

Process the oldest due delivery; this is the Vercel cron target.

http://localhost:8000/internal/email-deliveries/run
Authorization: Bearer YOUR_CRON_SECRET
Expect
200 with status processed or empty.
Failure
Missing/wrong Bearer secret returns 401.
Caveat
At most three attempts; database leasing handles duplicate cron invocations.
